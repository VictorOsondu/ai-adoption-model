# Contributing

This repository holds the canonical spec for a framework, so the bar for changes to the model itself is high — but there are three kinds of contribution that are genuinely welcome.

## What's welcome

- **Corrections** — a typo, a broken link, an unclear sentence, a factual slip. Open a PR or an issue.
- **Case studies** — you applied the model in a real setting and learned something about how a stage behaves in practice. These are gold. Open an issue describing it first so we can agree where it fits.
- **Translations** — a faithful translation of the model into another language, credited to you.

## What isn't

- Renaming or reordering the stages, or adding new ones. The model is deliberately fixed at six stages; changes to the structure happen through a versioned release, not a PR.
- Vendor placements, affiliate links, or "you should mention our tool" additions. This is a framework, not a directory.

## How to submit

1. Open an issue first for anything larger than a typo, so we can agree the change before you spend time on it.
2. Keep the voice consistent — plain, specific, UK English, no hype.
3. PRs are reviewed as promptly as a one-person team reasonably can. If a change doesn't fit, you'll get a clear, polite reason.
